Detecting code smells in Java, and fixing the ones that are safe to fix

My bachelor thesis at UBT, 2026. A tool that reads a Java codebase, flags four classic design problems in three independent ways, and writes a patch you can review with git before anything changes.

Rules and metrics
Detection strategies from Lanza and Marinescu over 26 class and method metrics, with thresholds taken from the literature.
Machine learning
Random forest and gradient boosting models trained on the MLCQ dataset, where professional developers labelled each sample.
Refactoring engine
Deterministic rewrites of the syntax tree from Fowler's catalogue, each one checked by compiling it with javac. A rewrite it can't prove safe is refused and reported, not applied.

The output is a unified diff, so nothing touches the code until a person has read it. Run as a build step, the tool exits with code 3 when a finding reaches the chosen severity. 

python -m javasmell path/to/project \
    --format patch --out fixes.patch
git apply --check fixes.patch

Python 3.13, tree-sitter, scikit-learn, FastAPI, React and TypeScript. Every push runs ruff, mypy and pytest, and dependencies are pinned so the published numbers can be reproduced.
