Featured project In development

Pragu finds accessibility barriers in Android apps before users hit them

Prag is Albanian for threshold: the step a wheelchair can't climb. Pragu reads an app the way the TalkBack screen reader does, marks each barrier on a screenshot, and says who it affects and how to fix it.

The problem

Most developers never use their own app with a screen reader, at a large text size or with low vision, so barriers ship unnoticed: a button TalkBack can only announce as "button", text too faint to read, a target too small to tap. Since June 2025 the European Accessibility Act has covered many apps sold in the EU, including e-commerce, banking and transport.

The approach

One command captures what TalkBack sees, plus a screenshot, without changing the app's code. Rules run on that capture, and every rule's precision is measured on labelled screens before it ships, because a false alarm costs a team's trust. 

$ pnpm pragu scan --from-capture bench/recordings/rn-shop/cart.json
Pragu scanned dev.pragu.fixtures.rnshop on sdk_gphone64_x86_64 (Android 16)
5 barriers: 4 errors, 1 warning, 0 info
  1. Warning: Touch target is too small · seed-tiny-dismiss (WCAG 2.5.8)
  2. Error: Interactive element has no accessible name · seed-unlabeled-remove (WCAG 4.1.2)
  …

How it works

  1. Agent A Kotlin app on the phone or emulator reads the app's accessibility tree and takes a screenshot.
  2. adb It talks to the computer only over adb. CI checks that it has no internet permission.
  3. Model A Node.js CLI turns the capture into a platform-neutral model and works out what TalkBack would announce.
  4. Rules WCAG 2.2 rules run on the model, with contrast measured from the screenshot's pixels.
  5. Report One offline HTML report for people, and versioned JSON for CI.

Built so far

  • The capture agent and the pragu scan CLI, on an emulator or a phone.
  • Seven rules: missing names on controls and images, unlabelled fields, hidden or stateless controls, text contrast and touch-target size.
  • The offline report, with fixes for React Native, Jetpack Compose and Android Views.
  • Pragu Bench, which scores every rule on labelled screens. CI fails any change that moves a score.
  • CI on GitHub Actions for the TypeScript packages and the Kotlin agent, plus a PRD, a technical design, a threat model and decision records.
